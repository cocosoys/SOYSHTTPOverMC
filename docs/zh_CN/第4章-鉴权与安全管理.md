# 第4章 鉴权与安全管理

SOYSHTTPOverMC 的安全模型由 **网关（GatewayFilter）** 承载：所有进入的 HTTP(S) 请求先过一条**策略链**（TLS 强制 → IP 白名单 → 限流 → 统一鉴权 → 访问限制器），任一策略 DENY 即短路拒绝。策略全部以 `gateway/` 目录下的 YAML 配置，`/soyshttp reload` 热重载。

## 4.1 网关目录结构

```
gateway/
├── config.yml            # enabled 总开关 / api-prefix / debug-events
├── https.yml             # TLS 证书来源与协议
├── policies/
│   ├── tls.yml           # order 5：明文 HTTP → 426 Upgrade Required
│   ├── ip-allowlist.yml  # order 10：IP 白/黑名单（精确 IP + CIDR）
│   ├── auth.yml          # order 20：统一凭证鉴权
│   ├── rate-limit.yml    # order 30：令牌桶限流
│   └── access-limiter.yml# order 31：窗口访问限制器
└── issuers/
    └── session-token.yml # 会话令牌颁发器（JWT）
```

## 4.2 各策略详解

### 4.2.1 tls.yml（强制 HTTPS）

```yaml
enabled: true
host: ""        # 426 Location 使用的主机名（留空用 https.yml 的 host）
```

明文 HTTP → `426 Upgrade Required`，Location 指向同端口 `https://`。

### 4.2.2 ip-allowlist.yml（IP 白/黑名单）

```yaml
enabled: false
default: allow        # allow=列表即黑名单（命中拒绝）；deny=列表即白名单（仅命中放行）
list: []              # 例: ["127.0.0.1", "192.168.1.0/24"]
trust-proxy: false    # true 时优先取 X-Forwarded-For 首个 IP（前置可信代理场景）
```

### 4.2.3 rate-limit.yml（令牌桶限流）

```yaml
enabled: false
scope: ip             # ip | key（按 IP 或 API Key 维度）
rpm: 60               # 每分钟补充
burst: 10             # 突发上限
```

超限 → `429 + Retry-After`。

### 4.2.4 access-limiter.yml（窗口访问限制器）

```yaml
enabled: false
path-patterns:
  - name: "ip访问限制"
    description: "所有用户的ip仅能访问50次网页，200次api，一小时后刷新次数"
    scope: ip         # ip | key | path
    limit: 50         # 每窗口最大访问次数
    window-seconds: 3600
```

被动刷新：无后台定时任务，仅在被访问时检测窗口是否已过。

### 4.2.5 auth.yml（统一凭证鉴权，order 20）

```yaml
enabled: true
header: X-API-Key            # 静态 Key 请求头名
login-provider: ""           # 登录插件提供者名（如 authme；留空=自动选用第一个可用）
keys: []                     # 静态凭证（X-API-Key 头 或 Authorization: Bearer 均可匹配）
paths: [/api/*]              # 空=保护所有路径；* 全匹配；/api/* 前缀匹配
exempt: [/ping, /whoami, /auth/login, /auth/issue, /auth/mode, /auth/status, /homepage/config, /homepage/live]
accept:
  header: true               # 接受 X-API-Key 头
  bearer: true               # 接受 Authorization: Bearer <key>
  basic: true                # 接受 Authorization: Basic（用户名=key）
  cookie: true               # 接受 Cookie（值由启用的颁发器校验）
```

凭证匹配规则：静态 `keys` 与任一启用颁发器匹配即放行，全部不匹配 → 401。

### 4.2.6 https.yml（TLS）

```yaml
enabled: true
host: ""
cert: ""          # PEM 证书路径（可选）
key: ""           # PEM 私钥路径（可选，PKCS8）
keystore: ""      # PKCS12 keystore 路径（可选，优先于 cert/key）
keystore-pass: ""
key-pass: ""
enabled-protocols: []   # 留空=全开 TLSv1.0~1.3（JVM 不支持的自动跳过）
min-tls: TLSv1.1
```

证书来源优先级：`keystore(PKCS12) > cert+key(PEM, 私钥须 PKCS8) > 留空自动 keytool 自签（纯离线）`。公网浏览器不信任自签属已知取舍，API 客户端可用 `-k` 或固定证书解决。

## 4.3 凭证体系

### 4.3.1 凭证来源（三种）

1. **X-API-Key 头**（默认头名 `X-API-Key`）：匹配静态 keys；
2. **Authorization**：`Bearer <key>`（匹配静态 keys）或 `Basic`（用户名=key）；
3. **Cookie**：请求携带的 cookie 交由 `gateway/issuers/` 下启用的颁发器校验（如 `soys_session`）。

### 4.3.2 session-token.yml（会话令牌颁发器）

```yaml
enabled: true
cookie-name: soys_session
ttl-seconds: 86400
clock-skew-seconds: 30    # 跨服时钟容差（校验 exp/iat）
```

- 启用后 `/soyshttp key <subject>` 下发会话令牌，同一 token 可作 X-API-Key / Bearer / Cookie 使用；
- 令牌为**内存态**，服务重启后全部失效；
- 会话令牌带 `adm` 标记（服主手动下发）时视为最高权限，免权限访问全部 API；
- JWT 密钥：优先从共享存储（MySQL，跨服统一）读取，否则回退本地 `token.key` 文件（跨服验签可能不一致——见 config.yml 日志）。

## 4.4 网页登录与登录插件接入

### 4.4.1 LoginProvider SPI

core 定义登录插件提供者 SPI（`web/gateway/policy/auth/bridge/spi/LoginProvider`），登录插件经 `LoginProviderFactory` 注册。内置 `AuthMeLoginProvider`：检测到 AuthMe 后自动注册。`gateway/policies/auth.yml` 的 `login-provider` 可指定；留空自动选用第一个可用的。

- **有登录插件**：网页登录窗口 `/api/auth/login` 用密码校验（AuthMe），成功后为玩家签发会话令牌；
- **无登录插件**：网页登录进入**免密码模式**——仅输入用户名即可签发令牌（令牌权限受 `PlayerPermissionService` 约束，即玩家在游戏内拥有的权限其令牌也拥有）。

### 4.4.2 自动登录（auth.yml auto.login.*）

```yaml
auto:
  login:
    ttl:
      enable: true      # 记住我（设备免登录）总开关，默认 true
      activetime: 7     # 记住我凭证有效期（天），默认 7
    ip:
      enabled: false    # 旧"IP 匹配免登录"开关，默认关闭
```

- **记住我**：登录时按前端"记住我"勾选签发长期设备凭证 Cookie（`soys_remember`，HttpOnly），后续访问 `/api/auth/status` 自动登录；
- **IP 匹配免登录**（默认关）：旧行为按"游戏在线 + 网页IP == 游戏IP"自动登录；IP 无法精准到个人设备，同 NAT 下会误伤他人，故默认关闭。

### 4.4.3 登录窗口端点（/api/auth/*）

| 端点 | 说明 |
| --- | --- |
| `/api/auth/login` | 登录窗口登录接口（登录前无凭证，默认豁免鉴权） |
| `/api/auth/issue` | 票据 / 免密登录提交 |
| `/api/auth/mode` | 前端登录页模式探测（密码模式 / 免密模式） |
| `/api/auth/status` | 登录状态检查（未登录时调用，支持 remember 自动登录） |

`/auth/logout`、`/auth/me` 仍需凭证。

## 4.5 权限判定（组合权限服务）

### 4.5.1 判定顺序

`CombinedPermissionService`（继承 `PlayerPermissionService`）：

1. Bukkit 原生权限（在线）+ 离线 OP 检查（返回 true 直接通过，性能优化）；
2. 遍历 `ProviderRegistry` 中所有已配置权限插件提供者：在线调 `hasPermission(player, perm)`，离线调 `hasOfflinePermission(playerName, perm)`，任一 true 通过；
3. 全部 false → 拒绝（403）。

### 4.5.2 config.yml 权限配置

```yaml
permission:
  providers: []            # 留空=所有已安装的权限插件自动加入；指定列表=只使用列表
  offline-fallback: op-only   # 离线玩家降级：op-only / local / false
```

支持插件：`luckperms`（推荐，离线查询）、`permsex`（离线查询）、`essentials`、`essentialx`、`local`（内置本地表，在线/离线均可查）。

### 4.5.3 离线降级策略

| 值 | 行为 |
| --- | --- |
| `op-only`（默认） | 仅 OP 玩家放行（读 ops.json） |
| `local` | 查插件内置本地权限表（data/soys_perm_*.yml 或 SQL 表） |
| `false` | 所有离线玩家拒绝（最严格） |

## 4.6 本地权限表（/soyshttp perm）

配套 `offline-fallback: local`（或 `providers: ["local"]`），插件内置用户/组/权限表：

```
/soyshttp perm group create <id> [weight] [display]      # 建组（weight 越大优先级越高）
/soyshttp perm group delete <id>                         # 删组（连带权限与成员引用）
/soyshttp perm group weight <id> <weight>                # 调整权重
/soyshttp perm group add|remove <id> <permission>        # 组加/删权限
/soyshttp perm group list                                # 组列表
/soyshttp perm user <player> group add|remove <group>    # 用户入组/出组
/soyshttp perm user <player> add|remove <permission>     # 用户直接权限
/soyshttp perm user <player> list                        # 查看用户有效权限（含组继承）
/soyshttp perm user <player> expiry <epoch|clear>        # 用户级过期时间
/soyshttp perm check <player> <permission>               # 调试：判定结果
/soyshttp perm reload                                    # 重载提供者链
```

规则（真实实现）：

- **节点匹配**：`:` 等价 `.`（`test:ping` ≡ `test.ping`）；`-` 前缀为 negative（写库时剥离前缀存 `permission + negative=true`）；`*` 全量；`a.*` 段通配；
- **组不支持继承**（一期扁平：组只含权限）；
- **过期粒度**：仅用户级 expiry（yyyy-MM-dd HH:mm:ss，空=永久）；过期用户判定为拒绝；
- **存储**：`data/soys_perm_group.yml` + `data/soys_perm_user.yml`（或 SQL 表，若启用 SQL 后端）；
- **用户主键**：`uuid`（玩家在线且判定时未记录 uuid 则自动补录；改名后以 uuid 匹配优先，uuid 不存在才以名称匹配）；
- **缓存**：判定每次查 ORM（无额外缓存层）。

## 4.7 自定义安全策略（ExtensionApi）

第三方插件可实现 `SecurityPolicy` 注入网关策略链（gateway/policies/ 之外），按 order 参与排序，DENY 短路、异常 fail-closed，`/soyshttp reload` 后保留：

```java
api.getExtension().registerPolicy(new SecurityPolicy() {
    public int order() { return 15; }                       // 插在 ip-allowlist 与 auth 之间
    public PolicyResult check(GatewayContext ctx) { ... }   // ALLOW / DENY
});
```

## 4.8 门面能力组 3：AuthCredentialApi

`api.getAuthCredential()`：

| 方法 | 说明 |
| --- | --- |
| `registerCredentialIssuer(String name, Supplier<CredentialIssuer> factory)` | 注册凭证颁发器工厂（登录插件接入点） |
| `isAuthEnabled()` | auth 策略是否启用 |
| `getIssuerNames()` | 已启用的颁发器名列表 |
| `issueCredential(subject)` / `issueCredential(issuerName, subject)` | 为已认证主体签发凭证 |
| `issueCredential(subject, claims)` / `issueCredential(issuerName, subject, claims)` | 签发携带自定义 claims 的凭证（键限 `[a-zA-Z0-9_-]{1,32}`、值限 256 字符；保留键 `sub/mode/exp/iat/jti/adm` 不可用） |

```java
IssuedCredential cred = api.getAuthCredential().issueCredential("Steve");
// cred.token() / cred.expiresAt() ...
```

## 4.9 版本注意

- TLS 视运行 JDK：1.6.4 若运行于 JDK7，TLS 上限 TLSv1.1/1.2，仅支持 TLSv1.0 的老客户端可能握手失败；
- 群组服下 JWT 密钥建议启用 MySQL 共享存储（`storage.cross-server: true`），保证各子服验签一致。
