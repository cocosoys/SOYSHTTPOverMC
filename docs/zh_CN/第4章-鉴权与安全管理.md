# 第四章 鉴权与安全管理

暴露接口后，如何保护它们？本插件提供了一条**网关安全策略链**，覆盖 TLS、IP 白名单、API Key 鉴权、令牌限流等。你也可以把登录插件（如 AuthMe）的账号体系接入，或在自己的插件里贡献自定义安全策略。

所有凭证相关能力通过能力组 3（`AuthCredentialApi`）提供；自定义策略通过能力组 8（`ExtensionApi`）提供。

## 4.1 网关策略链模型

网关在把请求交给业务路由（你的接口 / 网页）之前，会依次经过：

1. **SecurityPolicy（安全策略）**：开发者可贡献的自定义策略，按 `order` 排序；
2. **GatewayFilter（网关过滤器）**：内置核心过滤器，内部再按固定顺序执行下列内置策略。

内置策略的默认 `order`（值越小越先执行）：

| 策略 | order | 作用 |
| --- | --- | --- |
| `TlsPolicy` | 5 | 强制 TLS（明文 HTTP 升级 / 拒绝） |
| `IpAllowlistPolicy` | 10 | IP 白名单（CIDR 匹配） |
| `AuthPolicy` | 20 | 凭证校验（`X-API-Key` / `Authorization` / `Cookie`） |
| `RateLimitPolicy` | 30 | 令牌桶限流（超额 429） |

### 4.1.1 短路与失败封闭

- 任一策略返回 **DENY** → 立即短路，后续策略不再执行，直接返回对应拒绝响应；
- 策略执行**抛异常** → **fail-closed**（默认返回 500），避免异常被吞掉导致未授权访问。

### 4.1.2 配置目录化

网关配置集中在 `gateway/` 目录：

```
gateway/
  config.yml          # 全局开关、api-prefix 等
  https.yml           # TLS 证书与端口
  policies/*.yml      # 各策略参数（IP 白名单、限流阈值等）
  issuers/*.yml       # 凭证颁发器配置（auth 策略引用的颁发器）
```

首次启动会自动 `saveResource` 生成默认配置。修改后可用 `soyshttp reload` 热加载。

## 4.2 各内置策略说明

### 4.2.1 TlsPolicy（order 5）

确保 Web 流量走 TLS。明文 HTTP 请求会被要求升级（返回 `426`），避免明文暴露凭证。服务器端口上所有 Web 请求都经 TLS 终止后进入内部处理。

### 4.2.2 IpAllowlistPolicy（order 10）

按 CIDR 匹配客户端 IP，不在白名单则拒绝。适合仅允许内网 / 特定机器访问管理接口。配置位于 `gateway/policies/` 下的白名单文件。

### 4.2.3 AuthPolicy（order 20）

校验请求携带的凭证，支持三种来源（按优先级）：

- 请求头 `X-API-Key`；
- 请求头 `Authorization`（Bearer Token）；
- Cookie（会话令牌）。

校验通过则放行并把凭证解析为 `ApiRequestContext` 中的 `credential` / `playerName`，供你的接口使用。

### 4.2.4 RateLimitPolicy（order 30）

令牌桶限流，防止接口被刷。超额返回 `429 Too Many Requests`。阈值在策略配置中设定。

## 4.3 凭证颁发

### 4.3.1 颁发器与 IssuedCredential

`CredentialIssuer` 是凭证颁发器的抽象。已启用的颁发器会在 `auth` 策略中生效。你可以查询与签发：

```java
api.getAuthCredential().isAuthEnabled();                 // 是否有启用的 auth 策略
List<String> names = api.getAuthCredential().getIssuerNames();  // 列出已启用颁发器名

// 为已认证主体签发凭证（无启用颁发器返回 null）
IssuedCredential cred = api.getAuthCredential().issueCredential("Steve");
// 指定颁发器
IssuedCredential cred2 = api.getAuthCredential().issueCredential("session", "Steve");
```

`IssuedCredential` 包含令牌字符串与元数据，可直接返回给前端或写入 Cookie。

### 4.3.2 会话令牌（JWT HS256）

默认会话颁发器使用自实现的 JWT（HS256），令牌格式为 `st_<h>.<p>.<sig>`：

- `jti` 作为令牌唯一标识，登出时放入黑名单使其失效；
- 签名密钥持久化于 `data/token-secret.key`，`reload` 复用同一密钥 → **旧令牌不会因重启而失效**；
- 支持携带自定义 claims（键限 `[a-zA-Z0-9_-]{1,32}`，值限 256 字符；保留键 `sub/mode/exp/iat/jti/adm` 不可用）：

```java
Map<String, String> claims = new java.util.LinkedHashMap<>();
claims.put("scope", "readonly");
IssuedCredential cred = api.getAuthCredential().issueCredential("Steve", claims);
```

### 4.3.3 管理密钥（admin key）

管理密钥前缀为 `ak_`，携带 `adm=1` 声明，拥有最高权限（仅由 `soyshttp key <subject>` 命令签发）。在网关中 admin 令牌豁免权限判定。

### 4.3.4 离线 Cookie 自动升级

当玩家在游戏内登录后，系统会通过 `ApiRegistry` 的 `tokenUpgrader` 与线程局部 `pendingHeaders` 把离线 Cookie 换发为在线令牌（响应头 `Set-Cookie` + `X-Soys-New-Token`），前端 `soys-auth.js` 检测到后自动重试一次。这样网页端能平滑从“匿名”升级到“已登录玩家”身份。

## 4.4 登录插件接入（LoginProvider SPI）

若你的服务器用了 AuthMe 等登录插件，希望用其账号体系做 Web 鉴权，可实现 `LoginProvider` SPI 并注册：

```java
api.getExtension().registerLoginProvider(myLoginProvider);
```

`LoginProvider` 负责：

- 校验密码（`AuthLoginBridge.verifyPassword` 委托它）；
- 提供登录后的令牌签发；
- 让 Bot 等无头账号**免登录**进入（反射注入 AuthMe 的 `UNRESTRICTED_NAMES` 纯内存，不写 config.yml，避免污染配置）。

内置已实现 `AuthMeLoginProvider`（软依赖延迟加载，避免 `NoClassDefFoundError`）。其密码校验并非依赖不可靠的 `AuthMeApi.checkPassword`，而是反射 `AuthMe.database` + `PasswordSecurity.comparePassword(...)` 做纯比对。

> 注意事项：校验器必须随 bridge 创建时**立即 bind**；`AuthMeApi.checkPassword` 不可靠，须用上述反射比对方式。

## 4.5 自定义安全策略

除了内置策略，你的插件可贡献自己的 `SecurityPolicy`，注入网关策略链：

```java
api.getExtension().registerPolicy(mySecurityPolicy);
```

规则：

- 按 `order` 参与排序；
- 返回 DENY 即短路；异常时 fail-closed；
- 在 `soyshttp reload` 后**保留**（无需重复注册）。

常用于插件自带限流段、灰度分流、维护页等。

## 4.6 最佳实践与跨服一致性提醒

- **跨服 JWT 验签**：各子服首次启动会各自随机生成 `token-secret.key`，导致 lobby 签发的令牌在 survival 不被认可。**跨服一致需手工把同一 `token-secret.key` 复制到各子服**（或未来做密钥集中下发）。
- **jti 黑名单 / 限流桶 / 统计 / AuthMe 数据均每服独立**：登出不同步、限流可轮服绕过、审计碎片化。最小共享面是 JWT 密钥 + jti 黑名单表（表结构需带 `server_id` 维度防双服写冲突）。
- **最小权限**：管理接口务必加 `@ApiPermission` 并注册 `PermissionService`；admin key 仅用于运维，不要下发到前端。
- **失败封闭**：自定义策略抛异常即 500，请确保策略逻辑健壮，不要把正常放行路径之外的异常吞掉。
