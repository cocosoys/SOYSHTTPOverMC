# 第6章 进阶能力与最佳实践

## 6.1 能力组 5：HTTP 客户端（HttpClientApi）

`api.getHttpClient()`：

| 方法 | 说明 |
| --- | --- |
| `sendHttp(method, url, headers, body)` | 对外真实 HTTP 请求（任意方法/URL/头/体），返回 `HttpResponse`（状态码+头+体）；连接失败抛 `HttpClientException` |
| `sendGet(url [, headers])` | GET 便捷 |
| `sendPost(url [, headers], body)` | POST 便捷 |
| `callLocalApi(method, path, headers, body)` | 对内回环：直接调用本插件自身已注册的 API（绕过网络，等价本地分发） |
| `sendApi(method, logicalPath, headers, body)` | 通用发送：`resolveUrl` 补全前缀后**本地分发**（注解层 `@ApiPublic/@ApiPermission` 判定照常生效）；未命中路由返回 null |
| `resolveUrl(logicalPath)` | 解析本服 HTTP 可访问的完整路径（自动补三种前缀，见下） |
| `getApiPrefix()` | 注解式 API 全局前缀（`/api`） |
| `isAuthEnabled()` | 网关 auth 是否开启 |

> 前缀家族（`serverPrefix()` / `apiPrefix()` / `pluginsPrefix()` / `apiFullPrefix()` / `pageFullPrefix()` / `webResourcePrefix()` / `fullPathPrefix()` / `scheme()` / `host()` / `port()` / `pageBase()` / `spaFallback()` / `fpEnabled()` / `fpStrict()`）统一在**能力组 4 ApiToolkitApi**（`api.getToolkit()`）中提供，完整签名见附录 A.5。

### 6.1.1 resolveUrl 三段前缀

`resolveUrl("/status")` 自动补全：

1. **/api 前缀**：注解式 API 全局前缀（恒生效）；
2. **服务器前缀**：群组服自动补 `/server/<本服名>`（跨服路由）；独立服无此概念 → 留空；
3. **插件名前缀**：调用方为第三方插件时自动补 `/plugins/<插件名>`（沿调用栈识别；主插件自身调用不补）。

例：第三方插件 Foo 调 `resolveUrl("/status")` → 独立服 `/api/plugins/Foo/status`；群组服 `/server/lobby/api/plugins/Foo/status`。因此**同一段代码可直接通用于单服务器与群组服**。

## 6.2 能力组 6：扩展接入（ExtensionApi）

`api.getExtension()`：

| 方法 | 说明 |
| --- | --- |
| `registerLoginProvider(LoginProvider)` | 注册登录插件提供者（实现 SPI 一行接入，网关自动完成密码校验/免登录/玩家登录签发） |
| `registerSubCommand(SubCommand)` | 注册 `/soyshttp`（或 `/shttp`）子指令（继承 `SubCommand` 实现 4 个方法，op 校验 / help 聚合自动完成） |
| `registerWebInterceptor(WebInterceptor)` | 注册请求级拦截器：在网关策略之后、业务路由之前执行，可改写 path/请求头或按自定义规则短路返回（SSO 校验、维护页、灰度分流） |
| `registerPolicy(SecurityPolicy)` | 注入自定义安全策略（见第 4 章 4.7） |

### 6.2.1 自定义子指令

```java
public class MySub extends SubCommand {
    public String name() { return "mycmd"; }
    public String permission() { return "soyshttp.admin"; }
    public String usage() { return "/soyshttp mycmd <arg>"; }
    public boolean isHide() { return false; }

    public void execute(CommandSender sender, String[] args) {
        msgT(sender, "command.mycmd.done", "§a完成: {0}", args.length > 0 ? args[0] : "?");
    }
    public List<String> tabComplete(CommandSender sender, String[] args) { ... }
}

// 注册（需宿主 onEnable 完成后）
api.getExtension().registerSubCommand(new MySub());
```

子指令基类 `SubCommand` 提供 `msg` / `msgT`（自动加 `§a[SOYSHTTPOverMC]§r` 前缀 + i18n）等便捷方法。

### 6.2.2 请求级拦截器

```java
api.getExtension().registerWebInterceptor((ctx, chain) -> {
    if (ctx.getIp().startsWith("127.")) return chain.next(ctx);   // 放行
    return ApiResponse.error(403, "仅允许本地访问");              // 短路
});
```

多个拦截器按注册顺序执行；可在拦截器内改写 `ctx` 的 path / 请求头。

## 6.3 国际化（I18n）

- `language.yml` 的 `current` 指定语言（默认 `zh_cn`），`/soyshttp lang <代码>` 切换并持久化；
- `rule`：`internationalization`（默认，en_us 为基底叠加目标语言）/ `clear` / `overlay`；
- `sources`：额外语言源（其他插件/管理员提供），支持文件、文件夹（`<目录>/<语言代码>.yml` 约定）、网络 URL（可反引号包裹；`{0}` 语言占位符）；可用 `/soyshttp lang sources ...` 管理（on/off/download/update/remove/info）；
- 代码侧：`I18n.t(key, fallback, args...)` 取翻译；日志用 `LogKit` 的 `infoT/warnT/errorT/debugT(key, fallback, args...)`；
- 语言包放在 `plugins/SOYSHTTPOverMC/language/`（内置 `zh_cn.yml` / `en_us.yml`），平铺点路径键。

## 6.4 日志管控

- `config.yml log.level`：OFF / ERROR / WARN / INFO（默认）/ DEBUG / TRACE；
- `/soyshttp log [级别]` 或 `/soyshttp reload` 动态调整；
- 全部插件日志经 LogKit 门面统一过滤，`@CustomLog` 生成 `log` 对象。

## 6.5 热重载（/soyshttp reload）

`reloadHttpConfig()` 依次：

1. 重读 config.yml / language.yml / pages.yml；
2. 重建网页访问权限检查器；
3. 重设日志级别；
4. 重建存储后端（initStorage）；
5. 重建网关策略链与 TLS；
6. 重建组合权限服务并注入 ApiRegistry；
7. 重新接入登录桥（AuthLoginBridge）与登录提供者；
8. 按 tag 卸载旧 pages.yml 页面并重新登记；
9. 更新前端 home 规格；
10. 依次调用所有 `ReloadHttpConfigHandler` 钩子；
11. 广播 `HttpConfigReloadEvent`。

> 注意：`gateway/config.yml` 的 `api-prefix` 修改需重启服务器（reload 不重注册路由）；`web.home` 修改也需重启（或 reload 后由 WebFrontendHandler 热替换生效）。

## 6.6 群组服（BungeeCord / Velocity）

`config.yml`：

```yaml
proxy:
  server-name: ""       # 该子服在代理中的唯一名称（对应 BungeeCord servers.<name>）
  proxy-address: ""     # 经代理连接的地址 host:port（必须填，否则跨服 Forward 被丢弃）
mc:
  public-host: ""       # 对外公网地址覆盖（可选）
  public-port: 0
  trust-proxy: true     # 信任代理注入的 X-Forwarded-For（恢复真实访客 IP）
```

- 每个子服 `server-name` 唯一且与代理注册名一致；
- `proxy-address` 留空则直连后端，Forward 被静默丢弃 → 跨服请求/发现全部失效；
- 请求头 `X-Soys-Source-Server` / `X-Soys-Trace-Id` 用于跨服关联（`ApiRequestContext.getSourceServer()` / `getTraceId()`）；
- JWT 密钥建议启用 MySQL 共享存储保证跨服验签一致（见第 5 章 5.6）。

## 6.7 HTTP 后端模式选择

| 模式 | 特点 | 适用 |
| --- | --- | --- |
| `direct` | 在 Netty IO 线程直接调用，延迟最低（<1ms），高并发阻塞 IO 线程 | 低并发 / 极简部署 |
| `netty-eventloop`（默认） | 提交独立 EventLoop 处理，延迟低（~1-3ms），不阻塞网关 IO | 常规推荐 |
| `memory-queue` | 有界队列 + worker，支持背压（满→503），延迟略高（~2-5ms） | 高并发防堆积 |
| `standalone-server` | 独立端口 Netty HTTP 服务器，不使用同端口嗅探，延迟最低、实现最简 | 不想占用 MC 端口时 |

配置 `http-backend.mode`；分模式参数在 `http-backend.<mode>.<key>`。版本限制见第 1 章 1.5。

## 6.8 多版本打包（Maven）

仓库分「两轨」产出：**1.8 及以上**由 core 单源码多目标（Maven profile）产出；**1.6.4 / 1.7.10** 由 adapter 独立模块产出完整 fat jar。

### 6.8.1 轨一：core 单源码多目标（1.8 – 1.21+）

同一 core 源码保持 **Java 8 字节码**（core/common 语法基线不变），通过 Maven profile 切换 spigot-api 编译基线与编译 JDK，一次产出多个 jar：

| 支持版本 | profile | 编译 JDK | spigot-api 编译基线 | plugin.yml `api-version` | 产物 |
| --- | --- | --- | --- | --- | --- |
| 1.8 | `-P1_8` | Java 8 | 1.8.8 | 留空 | `SOYSHTTPOverMC-1_8-<版本>.jar` |
| 1.9 – 1.12.2 | `-P1_12` | Java 8 | 1.12.2 | 留空 | `SOYSHTTPOverMC-1_12-<版本>.jar` |
| 1.13 – 1.16.5 | `-P1_16` | Java 8 | 1.16.5 | `1.13` | `SOYSHTTPOverMC-1_16-<版本>.jar` |
| 1.17 – 1.20.4 | `-P1_17` | Java 17 | 1.17 | `1.17` | `SOYSHTTPOverMC-1_17-<版本>.jar` |
| 1.20.5 – 1.21+ | `-P1_20_5` | Java 21 | 1.20.5 | `1.20.5` | `SOYSHTTPOverMC-1_20_5-<版本>.jar` |

构建示例（在仓库根执行；`-pl core -am` 自动带上 common）：

```bash
mvn -B clean package -DskipTests -P1_12 -pl core -am      # → SOYSHTTPOverMC-1_12-<版本>.jar
mvn -B clean package -DskipTests -P1_17 -pl core -am      # → SOYSHTTPOverMC-1_17-<版本>.jar（需 JDK17 toolchain）
mvn -B clean package -DskipTests -P1_20_5 -pl core -am    # → SOYSHTTPOverMC-1_20_5-<版本>.jar（需 JDK21 toolchain）
```

编译 JDK 由 Maven Toolchains 切换（`~/.m2/toolchains.xml` 声明各 JDK；或项目根 `toolchains.xml` 供本地使用）；CI（GitHub Actions）在 job matrix 中按 profile 切换 `setup-java` 版本（见仓库 `.github/workflows/release.yml`）。

### 6.8.2 轨二：adapter 独立 fat jar（1.6.4 / 1.7.10）

1.6.4 / 1.7.10 由 adapter 模块产出「完整 fat jar」（内嵌 adapter-common + common + core + 本模块实现 + META-INF/services），**直接放入对应版本服务端 plugins/ 即可运行**（craftbukkit 由服务端提供、不打入）：

| 支持版本 | 模块 | 编译基线（vendored lib/） | 产物 | 嗅探能力差异 |
| --- | --- | --- | --- | --- |
| 1.6.x（最低 1.6.4） | `adapter/v1_6x` | craftbukkit-1.6.4 | `SOYSHTTPOverMC-1_6-<版本>.jar` | 1.6.4 服务端无 Netty → **不支持同端口嗅探**，须 `http-backend.mode: standalone-server` 独立端口模式 |
| 1.7.x（目标 1.7.10） | `adapter/v1_7x` | craftbukkit-1.7.10 | `SOYSHTTPOverMC-1_7-<版本>.jar` | 1.7.10 已引入 Netty → **支持同端口嗅探**（「方法名+字段类型」双通道反射解析 v1_7_R4 的 ServerConnection） |

两模块均含版本特化适配：① **Platform 覆盖**（1.6.4 / 1.7.10 的 `YamlConfiguration.loadConfiguration(File)` 无显式编码入口 → `V1_6YamlIo` / `V1_7YamlIo` 自实现 UTF-8 读写，在 `V1_6PlatformAdapter` / `V1_7PlatformAdapter` 覆写 `loadYaml/saveYaml` 接入）；② **AdapterActivator 激活入口**（ServiceLoader 注册，由 adapter/common 的 `AdapterActivators` 发现）；③ **JDBC 兼容**（`V1_6JdbcCompat` / `V1_7JdbcCompat`）。

构建命令（先对根工程 install，再构建 adapter 聚合工程；adapter 子模块依赖 common/core，需先在本地仓库）：

```bash
mvn -B install -DskipTests                     # 根工程：common + core + adapter/common 装入本地仓库
mvn -f adapter\pom.xml -B clean package        # adapter 聚合：一次产出 1_6 / 1_7 全部 fat jar
mvn -f adapter\v1_7x\pom.xml -B clean package  # 或只构建某一版本
```

产物自动复制到仓库根 `output/`。版本差异（反射桥 / JdbcCompat / Platform 覆盖）全部收在 adapter 模块，core/common 保持 Java 8 语法且无 Bukkit 依赖。

## 6.9 最佳实践清单

### 6.9.1 附属插件：softdepend + 就绪判空 / 延迟注册

**清单**：第三方插件务必 `softdepend: [SOYSHTTPOverMC]`，onEnable 中判空；不确定加载顺序时监听 `SoysReadyEvent` 延迟注册。

**为什么**：`softdepend` 只保证「SOYS 存在时本插件排在它后面加载」，不保证顺序——若本插件先于 SOYS 加载，`register()` 时 SOYS 门面尚未初始化会失败。

**怎么做**：推荐继承 `SoysExpansion` + 一行 `register()`；加载顺序不确定时监听 `SoysReadyEvent`（宿主 onEnable 全部就绪后同步触发）。

plugin.yml：

```yaml
name: MyShop
version: 1.0.0
main: com.example.myshop.MyShopPlugin
api-version: 1.13
softdepend: [SOYSHTTPOverMC]
```

onEnable（判空 + 事件兜底）：

```java
public final class MyShopPlugin extends JavaPlugin {
    private boolean registered;

    @Override
    public void onEnable() {
        JavaPlugin soys = (JavaPlugin) getServer().getPluginManager().getPlugin("SOYSHTTPOverMC");
        if (soys != null && soys.isEnabled()) {
            registerExpansion();                 // SOYS 已就绪：直接注册
        } else {
            getServer().getPluginManager().registerEvents(new Listener() {
                @EventHandler
                public void onSoysReady(SoysReadyEvent e) { registerExpansion(); }
            }, this);                            // SOYS 未就绪：就绪事件兜底
        }
    }

    private void registerExpansion() {
        if (!registered) {
            registered = new ShopExpansion().register();   // 失败（identifier 冲突等）返回 false 并打 warn
        }
    }
}
```

扩展类骨架（SoysExpansion 专题见第 8 章）：

```java
public class ShopExpansion extends SoysExpansion {
    @Override public String getIdentifier() { return "shop"; }   // 唯一必填元信息

    @Override protected String resourceRoot() { return "dist"; } // 可选：自动托管 dist（惰性登记）

    @Override protected java.util.List<Object> buildControllers() {
        return java.util.Collections.singletonList(this);        // 本类即控制器
    }

    @GetMapping("/items")
    public AjaxResult items(ApiRequestContext ctx) { ... }
}
```

### 6.9.2 依赖面：provided scope 依赖 common / core

**清单**：编译期需要注解 / ORM / 宿主门面类时以 `provided` scope 依赖，运行期全部由 SOYS 提供。

**为什么**：`soyshttpovermc-common` 无 Bukkit 依赖（ORM / i18n / 日志门面等纯逻辑），可跨任意 JDK 编译；`SoysExpansion` 等宿主门面在 `core`。若打成 `compile` 会把 SOYS 的类重复打入你的插件，与本体类冲突。

pom.xml：

```xml
<dependency>
    <groupId>com.github.cocosoys.mc</groupId>
    <artifactId>soyshttpovermc-common</artifactId>
    <version>1.4.0</version>
    <scope>provided</scope>          <!-- 纯逻辑层：ORM / i18n / 日志 -->
</dependency>
<dependency>
    <groupId>com.github.cocosoys.mc</groupId>
    <artifactId>soyshttpovermc-core</artifactId>
    <version>1.4.0</version>
    <scope>provided</scope>          <!-- 宿主门面：SoysExpansion / 事件 / API -->
</dependency>
<dependency>
    <groupId>org.spigotmc</groupId>
    <artifactId>spigot-api</artifactId>
    <version>1.16.5-R0.1-SNAPSHOT</version>
    <scope>provided</scope>          <!-- Bukkit API 同样仅编译期 -->
</dependency>
```

不要把 common / core 打成 `compile` scope，也不要 shade 它们进自己的 jar。

### 6.9.3 控制器：统一返回 AjaxResult / 不在主线程做耗时操作

**清单**：控制器尽量返回 `AjaxResult`（或 `ApiResponse`），保持统一结构；不要在主线程做耗时操作（请求在 worker 线程处理）。

**为什么**：前端统一按 `{code, msg, data}` 解析；handler 运行在 worker 线程，直接阻塞主线程 API 或 `Thread.sleep` 会拖垮整个服务器。

```java
@RestController
@RequestMapping("/shop")
public class ShopController {

    @GetMapping("/items")
    public AjaxResult items(ApiRequestContext ctx) {
        List<Item> list = shopService.queryByOwner(ctx.getPlayerName());
        return AjaxResult.success(list);            // {"code":200,"msg":"操作成功","data":[...]}
    }

    @PostMapping("/buy")
    public AjaxResult buy(ApiRequestContext ctx, @RequestBody BuyRequest req) {
        if (!shopService.hasEnough(ctx.getPlayerName(), req.getPrice())) {
            return AjaxResult.forbidden("余额不足");  // {"code":403,"msg":"余额不足"}
        }
        shopService.buy(ctx.getPlayerName(), req);
        return AjaxResult.success("购买成功", null);   // 顶层 msg 自定义
    }
}
```

耗时任务（批量查询、外部请求）用 `getServer().getScheduler().runTaskAsynchronously(...)` 后台执行，结果经回调写回；绝不在 controller 内同步等待网络。

### 6.9.4 ApiRequestContext：getPlayer() 切主线程，循环内用 getPlayerName()

**清单**：`ApiRequestContext.getPlayer()` 会切主线程，勿在循环内调用；用 `getPlayerName()` 做稳定锚点；确需 Player 时用 `getSyncPlayer()` 单次同步获取。

**为什么**：`getPlayer()` 内部同步切到 Bukkit 主线程取在线玩家（离线时返回 null）；在循环 / 批量场景反复调用会造成主线程往返风暴。

```java
// ❌ 错误：循环内每次 getPlayer() 都切主线程
for (String itemId : itemIds) {
    Player p = ctx.getPlayer();
    if (p != null && p.hasPermission("shop.vip")) { ... }
}

// ✅ 正确：锚定 name（无主线程往返），需要 Player 时单次同步取
String name = ctx.getPlayerName();          // 稳定锚点，任意线程可用
if (!hasVip(name)) return AjaxResult.forbidden("需要 VIP");
Player me = ctx.getSyncPlayer();            // 仅这一次同步切主线程
if (me != null) me.sendMessage("购买成功");
```

### 6.9.5 网页权限：pages.yml 单页内联 permissions（AND）+ /soyshttp perm

**清单**：网页权限优先 `pages.yml` 单页内联 `permissions`（必须全部满足，AND 语义）；节点用 `/soyshttp perm` 授予；未配单页权限的页面回退 `pages.permissions` 全局规则。

**为什么**：页面鉴权在「打开页面前」由 PagePermissionChecker 执行，单页规则存在时优先于全局规则；`permissions: []` 显式空 = 无权限拦截，可规避全局规则误伤。

pages.yml：

```yaml
pages:
  permissions:                       # 全局规则（兜底）
    - "soys.page"
  page:
    "/web/plugins/shop/admin":
      resource: web/plugins/shop/admin.html
      permissions:                   # 单页规则：AND，覆盖全局
        - "soys.admin"
        - "shop.manager"
    "/web/plugins/shop/vip":
      resource: web/plugins/shop/vip.html
      permissions: []                # 显式空 = 该页无权限拦截
```

授予（op）：

```bash
/soyshttp perm user Steve add shop.manager        # 用户直接权限（- 前缀=否定；: ≡ .）
/soyshttp perm group create vip 50 VIP组          # 建权限组
/soyshttp perm group add vip shop.vip             # 组加权限
/soyshttp perm user Steve group add vip           # 用户入组
/soyshttp perm check Steve shop.manager           # 调试：判定该玩家是否拥有权限
```

### 6.9.6 缓存：热点资源 pinned 常驻、大文件阈值

**清单**：高价值资源加入 `web.cache.pinned` 常驻；超大文件关注 `web.large-file-threshold` 与 `web.large-file-max-bytes`（默认 128MB）。

**为什么**：LRU 缓存默认会淘汰低频热点；被淘汰的入口页 / 框架 JS 每次回源读盘 / 读 jar，体验与性能双降；超过阈值的响应走大文件惰性加载器，不占常规缓存。

pages.yml：

```yaml
web:
  cache:
    max-bytes: 16777216              # 缓存总上限 16MB
    max-entries: 1024
    ttl-seconds: 300
    pinned:                          # 常驻，永不淘汰
      - "/web/plugins/shop/index.html"
      - "/web/plugins/shop/static/css/app.css"
      - "/web/plugins/shop/static/js/chunk-vendors.js"
  large-file-threshold: 16777216     # 超过 16MB 的响应走大文件通道
  large-file-max-bytes: 134217728    # 单文件最大允许（默认 128MB）
```

### 6.9.7 公网部署：白名单 / 限流 / HTTPS / 信任代理

**清单**：公网部署 `ip-allowlist` 与 `rate-limit` 至少开一项；HTTPS 建议 `keystore(PKCS12)` 正式证书；`trust-proxy` 仅在后端确在可信代理之后保持 true。

**为什么**：插件把 HTTP 直接暴露在 MC 端口上，公网裸奔会被扫描器 / 爬虫打满；TLS 就地终止、三协议共存不另占端口；`trust-proxy` 若误开，伪造 `X-Forwarded-For` 可绕过白名单。

gateway/policies/ip-allowlist.yml：

```yaml
enabled: true
default: deny                 # 列表即白名单
list: ["127.0.0.1", "192.168.1.0/24", "114.114.114.114"]
trust-proxy: true             # 仅当确在 BungeeCord / Velocity 之后
```

gateway/policies/rate-limit.yml：

```yaml
enabled: true
scope: ip                     # ip | key（按 X-API-Key 维度）
rpm: 60                       # 每分钟补充
burst: 10                     # 突发上限，超限 429 + Retry-After
```

gateway/https.yml：

```yaml
enabled: true
keystore: plugins/SOYSHTTPOverMC/keystore.p12
keystore-pass: "********"      # PKCS12 优先于 cert/key PEM
min-tls: TLSv1.1
```

config.yml：

```yaml
mc:
  trust-proxy: true            # 与 ip-allowlist.trust-proxy 同语义：仅真实代理后开
```

### 6.9.8 多版本兼容：改动收口到 adapter

**清单**：版本差异集中在 adapter 模块（反射桥 / JdbcCompat / Platform 覆盖），core/common 保持 Java 8 语法且无 Bukkit 依赖，版本差异不进业务代码。

**为什么**：core 一份源码要产出 1.8 – 1.21+ 全部产物；若在业务代码里写 `if (版本 > 1.13)` 分支，等于把每个版本的差异平铺进所有模块，维护成本爆炸。

**怎么做**：新版本差异按「三件套」落 adapter：① Platform 覆盖（YAML 编码等宿主能力差异）；② AdapterActivator（ServiceLoader 激活入口）；③ JdbcCompat / 反射桥（API 形态差异）。示意骨架：

```java
// adapter/v1_7x/.../adapter/v1_7/V1_7PlatformAdapter.java（示意：继承默认实现，覆写编码差异）
public final class V1_7PlatformAdapter extends PlatformBukkitImpl {
    private final V1_7YamlIo yaml = new V1_7YamlIo();

    @Override
    public ConfigSection loadYaml(File file) {           // 1.7.10 无显式编码入口 → 自实现 UTF-8
        return yaml.load(file);
    }

    @Override
    public void saveYaml(ConfigSection cfg, File file) throws IOException {
        yaml.save(cfg, file);
    }
}
```

```java
// adapter/v1_7x/.../adapter/v1_7/V1_7SocketSnifferAdapter.java（示意：反射解析 v1_7_R4 ServerConnection）
public final class V1_7SocketSnifferAdapter implements SocketSnifferAdapter {
    public boolean supported() { return ServerVersion.atLeast("1.7"); }  // 见 adapter/common

    // 经「方法名+字段类型」双通道反射定位 ServerConnection，不直接 import v1_7_R4 具体类
}
```

`META-INF/services/com.github.cocosoys.mc.soyshttpovermc.adapter.spi.AdapterActivator` 声明 `V1_7AdapterActivator`，由 adapter/common 的 `AdapterActivators` 统一发现激活。
