# 第六章 进阶能力与最佳实践

本章汇总其余开放能力：对外发 HTTP 请求、跨服调用、Bot 管理、日志、工具函数、扩展接入点、事件监听，以及部署运维要点。

## 6.1 HTTP 客户端（HttpClientApi）

能力组 7。在你的插件里对外发起真实 HTTP 请求，或对本插件自身接口做本地回环调用。

### 6.1.1 对外请求

```java
HttpResponse r1 = api.getHttpClient().sendGet("https://example.com/api");
HttpResponse r2 = api.getHttpClient().sendPost("https://example.com/api",
    "{\"k\":\"v\"}".getBytes(StandardCharsets.UTF_8));

// 通用方法（任意方法 / 头 / 体）
HttpResponse r3 = api.getHttpClient().sendHttp("PUT", url, headersMap, bodyBytes);
```

`HttpResponse` 包含状态码、响应头与响应体。连接失败抛 `HttpClientException`。

便捷封装：`sendGet(url)`、`sendGet(url, headers)`、`sendPost(url, body)`、`sendPost(url, headers, body)`。

### 6.1.2 本地回环

`callLocalApi` 直接调用本插件自身已注册的 API（绕过网络，等价于本地分发），适合插件内部复用接口逻辑：

```java
Object result = api.getHttpClient().callLocalApi("GET", "/api/status", headers, null);
```

分发异常抛 `HttpClientException`。

## 6.2 跨服调用（CrossServerHttpClient）

能力组 9。群组服（BungeeCord / Velocity）架构下，插件间经本插件隧道调用另一子服的 API。**目标服无需对外暴露端口**。

```java
// 调用 lobby 子服的 /api/status
HttpResponse r = api.getCrossServer().callRemoteApi("lobby", "GET", "/api/status", headers, null);
HttpResponse g = api.getCrossServer().sendGet("survival", "/api/players");
HttpResponse p = api.getCrossServer().sendPost("lobby", "/api/broadcast", body);
```

调用经本服无头 Bot 隧道回环到本服 `McMessageHandler`，由其按 `X-Soys-Target-Server` 头中继到目标服；目标服处理后将响应按 `request_id` 关联合回。与 `HttpClientApi` 的区别：本接口走**群组服隧道**，目标服不暴露端口。

## 6.3 Bot 管理（BotManagementApi）

能力组 6。本插件内部维持一个主无头 Bot 承载隧道；你也可创建额外受管 Bot，或注册自定义通道。

```java
// 创建一个额外受管 Bot（独立通道 + 隧道），回连本服
BotManager.ManagedBot bot = api.getBotManagement().addBot("mybot", "my:channel");

// 复用主通道（多 Bot 分摊 / 双隧道冗余）
BotManager.ManagedBot bot2 = api.getBotManagement().addBot("mybot2");

// 在主 Bot 上注册自定义通道并监听下行消息
api.getBotManagement().registerChannel("my:channel", (channel, bytes) -> { /* 处理下行 */ });
api.getBotManagement().unregisterChannel("my:channel");

// 获取 / 踢出额外 Bot（主 Bot 不可踢）
BotManager.ManagedBot b = api.getBotManagement().getBot("mybot");
api.getBotManagement().kickBot("mybot");
```

- Bot 名称完全自定义（任意 ≤16 字符的合法离线名）；
- 若名称以 `bot.name-prefix`（默认 `__bot__`）开头，自动受 Bot 专属账号保护（登录 IP 白名单 + 对真实玩家隐藏，`BotGuardian`）。

## 6.4 日志（PluginLoggerApi）

能力组 5。包装日志工具，**自动识别调用插件并加 `[插件名]` 前缀**，便于在控制台区分来源。

```java
api.getLogger().logInfo("插件启动完成");
api.getLogger().logWarn("配置缺失，使用默认");
api.getLogger().logError("调用失败：" + e.getMessage());
api.getLogger().logDebug("调试信息");
boolean dbg = api.getLogger().isDebugEnabled();   // 当前是否包含 DEBUG 及以上
```

## 6.5 工具函数（ApiToolkitApi）

能力组 4。常用小工具：

```java
String json = api.getToolkit().toJson(myObject);          // 对象 → JSON 字符串
String ct = api.getToolkit().guessContentType("/a/b.png"); // 扩展名 → Content-Type
api.getToolkit().registerMimeType("vue", "text/html; charset=utf-8"); // 注册扩展名类型

// 向玩家发送可点击链接消息（url 完整；display 支持 %url% 与 %url_标签%，& 代替 § 颜色码）
api.getToolkit().sendLink(player, "https://myserver.com", "点击进入&l官网");
api.getToolkit().sendLink(onlinePlayers, url, display);   // 批量
```

## 6.6 扩展接入（ExtensionApi）

能力组 8。把你的插件更深地接入本插件。

### 6.6.1 注册登录插件提供者（LoginProvider SPI）

见第四章 4.4。实现 `LoginProvider` 后一行接入账号体系：

```java
api.getExtension().registerLoginProvider(myLoginProvider);
```

### 6.6.2 注册 /soyshttp 子指令

继承 `SubCommand` 实现 `name` / `requireOp` / `usage` / `detail` / `execute` / `tabComplete`，一行注册即可出现在 `soyshttp`（简写 `shttp`）命令树中，op 校验与 help 聚合自动完成：

```java
api.getExtension().registerSubCommand(new MySubCommand());
```

> 必须在宿主 `onEnable` 完成后调用（否则命令未初始化会抛异常）。

### 6.6.3 注册请求级拦截器（WebInterceptor）

在网关策略之后、业务路由之前执行，可改写 path / 请求头，或按自定义规则短路返回（SSO 校验、维护页、灰度分流）：

```java
api.getExtension().registerWebInterceptor(myInterceptor);
```

多个拦截器按注册顺序执行。

### 6.6.4 注册自定义安全策略（SecurityPolicy）

见第四章 4.5：

```java
api.getExtension().registerPolicy(mySecurityPolicy);
```

## 6.7 事件监听

本插件通过标准 Bukkit 事件总线暴露运行期信号，监听即可做审计、统计、安全告警、自动文档、生命周期联动。完整的使用与注册说明、线程模型、字段清单与范例见[第7章 事件系统（使用与注册）](第7章-事件系统（使用与注册）.md)。

事件全部位于包 `soys.soyshttpovermc.api.event`，按类别分为：

- **就绪事件**：`SoysReadyEvent`（SOYS 初始化完成，携带门面 `api`，用于延迟注册）。
- **网关请求类（异步，HTTP 工作线程触发）**：
  - `GatewayRequestEvent` —— 请求进入、**策略判定之前**（method/path/ip/tls/headers）；
  - `GatewayAccessDeniedEvent` —— 被安全策略拒绝（policyName/statusCode/reason）；
  - `GatewayRequestServedEvent` —— 请求处理完毕（statusCode/latencyUs，含隧道往返耗时）。
- **网关凭证事件（同步，主线程）**：`GatewayCredentialIssuedEvent`（subject/issuer/credential）。
- **API 生命周期（同步，主线程）**：`ApiRegisteredEvent` / `ApiUnregisteredEvent`（ownerPlugin + `List<ApiInfo>`，插件禁用时自动卸载并触发）。
- **API 访问（主线程）**：`ApiAccessEvent` 基类（携带 playerName / player / permission / credential），及按方法细分的 `ApiGetEvent` / `ApiPostEvent` / `ApiPutEvent` / `ApiDeleteEvent` / `ApiPatchEvent` / `ApiOtherEvent`。

基本用法（标准 Bukkit 注册，任意插件均可监听）：

```java
@EventHandler
public void onApiAccess(ApiAccessEvent e) {
    getLogger().info("API 访问: " + e.getPath() + " by " + e.getPlayerName());
}
```

> ⚠️ 所有事件均为只读观测、**不可取消**；异步的请求类事件监听器访问 Bukkit API 前需切回主线程。要拦截 / 改写请求请用 `registerWebInterceptor` 或 `registerPolicy`（见 6.6）。

## 6.8 部署与运维

### 6.8.1 命令参考（/soyshttp 或 /shttp，默认 op）

| 子指令 | 作用 |
| --- | --- |
| `reload` | 热加载网关与存储配置 |
| `key <subject>` | 为指定主体签发管理密钥（admin key，`ak_` 前缀） |
| `reconnect` | 重连无头 Bot 隧道 |
| `send <url\|/page> [文字] [玩家]` | 向玩家发送链接消息（`%url%` / `%url_标签%`，`&`→§，支持 `@a/@p/@r/@e/@s` 选择器） |
| `pages [all\|resources\|*]` | 列出已登记页面（默认仅可打开界面；`all` 含纯资源并标 [页]/[资源]/[跳转]） |
| `api [插件名]` | 列出已注册注解式端点（来自 `ApiRegistry.listEndpoints()`） |
| `tokens` | 列出当前令牌信息 |
| `help [子指令]` | 总览或某子指令的多行详细用法 |

Tab 补全与彩色输出已内置。

### 6.8.2 群组服部署要点

- 后端 `spigot.yml` 设 `bungeecord: true`（与 BungeeCord `ip_forward: true` 对齐）；
- `config.yml` 增加 `mc.public-host` / `mc.public-port`（对外地址覆盖，仅影响链接展示，不改 Bot 回连）；
- 防火墙仅放行代理 / 回环访问后端游戏端口，否则直连被拒；
- 代理侧 `BungeeCord/config.yml` 的 `connection_throttle` 建议设为 `-1`，放行浏览器并行 TLS 连接（否则并行连接可能被限流丢弃，表现为 `ERR_CONNECTION_ABORTED`）。

### 6.8.3 常见排障

- **HTTP 经代理端口出现 502**：说明请求没到达后端 `SocketSniffer`（隧道收不到）。在群组服下应**直连后端游戏端口**访问 Web，而非代理端口。
- **无头 Bot 断连 / NoClassDefFoundError**：通常是构建时旧源码污染 `target/classes`，需全量 clean 重编。
- **跨服 JWT 验签失败**：各子服 `token-secret.key` 不同，需复制同一密钥。
- **YAML 网页 body 恒空**：`Entry.resolveBytes()` 走 ClassLoader 必须剥去前导 `/`。
- **新增 MIME 不生效**：`Entry` 在请求时实时计算 Content-Type，先 `registerDirectory` 后 `registerMimeType` 也会生效；无需重新登记。
