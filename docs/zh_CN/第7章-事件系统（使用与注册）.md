# 第7章 事件系统（使用与注册）

SOYSHTTPOverMC 通过标准 Bukkit 事件总线对外暴露运行期各类信号，以便其他插件做**审计、统计、安全告警、自动文档、生命周期联动**等，而**无需改动插件内核**。

所有事件位于包 `soys.soyshttpovermc.api.event`（就绪事件亦在此包）：

- 网关事件基类 `GatewayEvent extends org.bukkit.event.Event`（含凭证下发事件）
- API 生命周期事件 `ApiRegisteredEvent` / `ApiUnregisteredEvent`
- API 访问事件 `ApiAccessEvent` 及按 HTTP 方法细分的子类
- 就绪事件 `SoysReadyEvent`（独立于 GatewayEvent 体系）
- 载体快照 `ApiInfo`（注册 / 卸载事件携带的端点信息）

> ⚠️ 这些事件均为**只读观测**，未实现 `Cancellable`。你不能通过监听它们来拦截或改写请求。若要介入请求处理（改写 path、拦截返回、自定义鉴权），请使用「请求级拦截器」`api.getExtension().registerWebInterceptor(...)` 或「自定义安全策略」`api.getExtension().registerPolicy(...)`（见第6章 6.6 / 第四章）。

## 7.1 两类基类与同步模型

| 基类 / 事件 | 声明 | 监听器实际运行线程 |
| --- | --- | --- |
| `GatewayEvent` 默认构造 | `super(true)` 异步 | 取决于子类（见下表） |
| `GatewayRequestEvent` / `GatewayAccessDeniedEvent` / `GatewayRequestServedEvent` | 异步 | **HTTP 工作线程**（嗅探器线程池） |
| `GatewayCredentialIssuedEvent` | `super(false)` 同步 | **主线程**（命令 / 登录流程） |
| `ApiRegisteredEvent` / `ApiUnregisteredEvent` | `super(false)` 同步 | **主线程**（框架强制切回） |
| `ApiAccessEvent` 及子类 | `super(true)` 但框架切回 | **主线程**（派发前经调度器切回） |
| `SoysReadyEvent` | 同步 | **主线程**（onEnable 末尾） |

要点：

- 网关请求类事件（`Request` / `Denied` / `Served`）在 HTTP 工作线程触发，**监听器异步**。需要访问 Bukkit API（查询玩家、写存档）时，请用 `Bukkit.getScheduler().runTask(plugin, ...)` 切回主线程。
- API 访问事件与注册 / 卸载 / 凭证 / 就绪事件均在**主线程**执行，可直接安全使用 Bukkit API。
- Bukkit 1.12.2 不允许「从主线程触发异步事件」，因此所有同步事件被框架强制在主线程派发；API 访问事件也从 worker 线程切回主线程再派发。

## 7.2 如何注册监听

事件就是普通 Bukkit 事件。任意插件按标准方式注册即可：

```java
import org.bukkit.event.EventHandler;
import org.bukkit.event.Listener;
import com.github.cocosoys.mc.soyshttpovermc.api.event.GatewayAccessDeniedEvent;

public class MyListener implements Listener {
    @EventHandler
    public void onDenied(GatewayAccessDeniedEvent e) {
        // 安全告警 / 审计 ...
    }
}

// 在你的 JavaPlugin#onEnable 中：
Bukkit.

getPluginManager().

registerEvents(new MyListener(), this);
```

- 事件包名属于 SOYS，但由服务端 `PluginManager` 统一派发，**任何插件**都能监听。
- 推荐以 `compileOnly` 方式依赖 SOYS 的 api 包以获得类型安全（也可仅依赖 Spigot API，运行时通过字符串包名引用）。
- 监听器抛异常**不影响**触发方（框架已 try-catch），但仍应自行保证健壮。

### 注册时机：SoysReadyEvent 的特殊性

若你的插件加载顺序不确定（可能早于 SOYS），不要直接在 `onEnable` 里调用 `HttpOverMcPlugin.getInstance().getApi()`（此时可能尚未就绪）。两种稳妥做法：

```java
// 做法 A：监听 SoysReadyEvent，在回调里注册（兼容「先于 SOYS 加载」）
Bukkit.getPluginManager().registerEvents(new Listener() {
    @EventHandler
    public void onReady(SoysReadyEvent e) {
        e.getApi().getApiRegistry().registerController(new MyApi());
    }
}, this);

// 做法 B：若 plugin.yml 声明 depend: [SOYSHTTPOverMC]（晚于 SOYS 加载，最常见），
//         onEnable 时 SOYS 已就绪，可直接注册：
HttpOverMcPlugin.getInstance().getApi().getWebPage().registerHome(this, "index.html");
```

> `SoysReadyEvent` 只在 SOYS 自身 `onEnable` 末尾触发**一次**。晚于 SOYS 加载的插件用做法 B 即可，无需等待该事件。

## 7.3 事件总览

| 事件类 | 触发时机 | 监听器线程 | 主要字段 | 典型用途 |
| --- | --- | --- | --- | --- |
| `SoysReadyEvent` | SOYS 初始化完成（一次） | 主线程 | `api` | 延迟注册 API / 网页 |
| `GatewayRequestEvent` | HTTP(S) 进入网关、**策略判定之前** | HTTP 工作线程 | method, path, ip, tls, headers | 访问审计 / 统计 / 限流计数 |
| `GatewayAccessDeniedEvent` | 请求被安全策略链拒绝（401/403/426/429/500…） | HTTP 工作线程 | method, path, ip, tls, policyName, statusCode, reason | 安全告警 / 封禁联动 / 审计 |
| `GatewayRequestServedEvent` | 请求处理完毕（含被拒 / 异常） | HTTP 工作线程 | method, path, ip, tls, statusCode, latencyUs | 指标统计 / 监控告警 |
| `GatewayCredentialIssuedEvent` | 凭证被颁发（`/soyshttp key` 或登录插件） | 主线程 | subject, issuer, credential | 通知客户端 / 登录联动 |
| `ApiRegisteredEvent` | 某插件注册一批注解式 API 后 | 主线程 | ownerPlugin, `List<ApiInfo>` | 路由审计 / 自动 OpenAPI / 权限联动 |
| `ApiUnregisteredEvent` | 某插件卸载其 API（禁用或显式） | 主线程 | ownerPlugin, `List<ApiInfo>` | 清理资源 / 撤销缓存 |
| `ApiAccessEvent`（基类） | 注解式 API 命中路由且**通过权限判定**后、处理器调用前 | 主线程 | httpMethod, path, apiName, permission, ownerPlugin, authenticated, playerName, player, credential | 全量访问审计 / 统计 |
| `ApiGet/Post/Put/Delete/Patch/OtherEvent` | 上述事件的按 HTTP 方法细分 | 主线程 | 同基类 | 仅关心特定方法时 |

## 7.4 各事件详解

### 7.4.1 SoysReadyEvent

```java
public class SoysReadyEvent extends Event {
    SoysHttpOverMcApi getApi();   // 对外门面：注册 API / 网页 / 凭证 / Bot / 拦截器
}
```

仅在 SOYS `onEnable` 末尾触发一次，携带已就绪的 `SoysHttpOverMcApi` 门面。见 7.2 的注册时机说明。

### 7.4.2 GatewayRequestEvent

```java
public class GatewayRequestEvent extends GatewayEvent {
    String getMethod();               // GET/POST/...
    String getPath();                 // 请求路径（如 /api/ping）
    String getIp();                   // 客户端 IP（穿透后的真实 IP）
    boolean isTls();                  // 是否经 TLS
    Map<String,String> getHeaders();  // 请求头（只读快照）
}
```

在网关策略判定**之前**触发。适合做访问日志、调用计数、自定义限流基数统计等。

> 🔧 监听器运行在 HTTP 工作线程（异步）。访问 Bukkit API 前请切回主线程：
> ```java
> @EventHandler
> public void onRequest(GatewayRequestEvent e) {
>     Bukkit.getScheduler().runTask(plugin, () -> { /* 主线程安全地使用 Bukkit API */ });
> }
> ```

### 7.4.3 GatewayAccessDeniedEvent

```java
public class GatewayAccessDeniedEvent extends GatewayEvent {
    String getMethod(); String getPath(); String getIp(); boolean isTls();
    String getPolicyName();   // 拒绝策略名：tls / auth / rate-limit / ip-allowlist / unknown
    int getStatusCode();      // 拒绝状态码：401/403/426/429/500/...
    String getReason();       // 拒绝原因文本
}
```

请求被安全策略链拒绝时触发。可据此做安全告警（如短时间大量 401 疑似爆破）、自动封禁、写入安全审计日志。

> 🔧 同样为异步事件，监听器线程为 HTTP 工作线程；需用 Bukkit 主线程调度访问 Bukkit API。

### 7.4.4 GatewayRequestServedEvent

```java
public class GatewayRequestServedEvent extends GatewayEvent {
    String getMethod(); String getPath(); String getIp(); boolean isTls();
    int getStatusCode();       // 最终状态码（含 2xx/4xx/5xx）
    long getLatencyUs();       // 端到端耗时（微秒，含隧道往返）
    long getLatencyMs();       // 同上，毫秒
}
```

请求处理完毕（无论成功、被拒还是异常）触发，位于 `finally` 块。`getLatencyUs()` 含隧道往返时长，适合做 P95/P99 监控、慢请求告警。

### 7.4.5 GatewayCredentialIssuedEvent

```java
public class GatewayCredentialIssuedEvent extends GatewayEvent {
    String getSubject();                 // 凭证主体（玩家 UUID / 用户名）
    CredentialIssuer getIssuer();        // 颁发器实例
    String getIssuerName();              // 颁发器名
    IssuedCredential getCredential();    // 下发的凭证（X-API-Key / Bearer / Cookie 三种形态）
}
```

凭证被颁发后触发（命令 `/soyshttp key` 或登录插件调用颁发器）。可监听后通知客户端、与自家登录系统联动。

> 同步事件，在主线程（命令 / 登录流程）触发，监听器可直接使用 Bukkit API。

### 7.4.6 ApiRegisteredEvent / ApiUnregisteredEvent

```java
public class ApiRegisteredEvent extends GatewayEvent {
    String getOwnerPlugin();      // 注册该批 API 的插件名（网关自动标记）
    List<ApiInfo> getApis();      // 本次注册 / 卸载的端点清单
}
// ApiUnregisteredEvent 字段相同
```

- 插件通过 `ApiRegistry.register(...)` 注册一批注解式端点后触发 `ApiRegisteredEvent`；
- 插件被禁用（`PluginDisableEvent`）时，框架**自动卸载**其名下全部 API 并触发 `ApiUnregisteredEvent`；也可在 `onDisable` 显式调用 `unregister(instance)` / `unregisterPlugin(name)`。

`ApiInfo`（端点快照，只读，不持有处理器实例，避免卸载后泄漏）：

```java
public class ApiInfo {
    String getHttpMethod();   // GET/POST/... 或 * 
    String getPath();         // 实际挂载路径（含 /api 前缀）
    String getApiName();      // 端点展示名（@ApiName）
    String getPermission();   // 所需权限（@ApiPermission，空=公开）
    String getHandlerClass(); // 处理器类全限定名
    String getOwnerPlugin();  // 注册插件名
}
```

典型用途：自动生成 OpenAPI / Swagger 文档、路由审计看板、权限联动（给 owner 插件自动授权）。

> 同步事件，在主线程触发。`ApiRegisteredEvent` 携带的 `List<ApiInfo>` 是本次注册**成功**的端点（被拒绝注册的重复路由不在其中）。

### 7.4.7 ApiAccessEvent 及方法子类

```java
public class ApiAccessEvent extends Event {
    String getHttpMethod();      // 实际请求方法
    String getPath();            // 完整路径（含 api-prefix，如 /api/status）
    String getApiName();         // 端点名（@ApiName）
    String getPermission();      // 权限（空=公开端点）
    boolean isPublic();          // 是否公开端点
    String getOwnerPlugin();     // 注册该 API 的插件名
    boolean isAuthenticated();   // 请求是否携带有效凭证
    String getPlayerName();      // token/cookie 解析出的玩家名（无凭证/非玩家令牌=null）
    Player getPlayer();          // 在线玩家实体（离线=null）
    CredentialPresentation getCredential(); // 解析出的凭证（可为 null）
}
```

一条注解式 API 请求**命中路由且通过权限判定后、处理器调用前**触发。框架通过 `ApiAccessEvent.forMethod(...)` 工厂按实际方法构造对应子类，且**子类与基类共享同一 HandlerList**：

- 监听 `ApiAccessEvent` → 收到**全部** API 访问（公开 + 权限，所有方法）；
- 监听 `ApiGetEvent` / `ApiPostEvent` / `ApiPutEvent` / `ApiDeleteEvent` / `ApiPatchEvent` / `ApiOtherEvent` → 只收到对应方法的访问。

> ✅ 监听器在**主线程**执行（框架已切回主线程），可直接安全使用 Bukkit API。
> ✅ 事件直接携带 `playerName` 与 `player` 实体，无需自行解析 token/cookie。

```java
@EventHandler
public void onAccess(ApiAccessEvent e) {
    if (!e.isPublic()) {
        getLogger().info("受限端点 " + e.getPath() + " 被 " + e.getPlayerName() + " 访问");
    }
}

// 仅关心 POST：
@EventHandler
public void onPost(ApiPostEvent e) {
    getLogger().info("POST " + e.getPath());
}
```

## 7.5 内置监听器（供参考）

框架自带两个内部监听器：

1. **`GatewayEventListener`**（`soys.soyshttpovermc.event`）：调试用。当 `gateway/config.yml` 的 `debug-events: true` 时，打印全部网关事件日志（`[EVENT] request/denied/served/...`）。它同时也是「如何监听网关事件」的范例实现；开关在启动 / 热重载后由插件同步。
2. **`ApiLifecycleListener`**（`soys.soyshttpovermc.event`）：监听 `PluginDisableEvent`，任一非本插件被禁用时，自动卸载其名下全部注解式 API 与登记网页，避免第三方插件残留导致内存泄漏 / 路由污染。

> 你的第三方监听器与这些内置监听器互不干扰，按需自行注册即可。

## 7.6 常见用法范式

### 访问审计 + 统计

```java
@EventHandler
public void onServed(GatewayRequestServedEvent e) {
    counter.increment(e.getPath(), e.getStatusCode());
    if (e.getLatencyMs() > 1000) alert("慢请求 " + e.getPath() + " " + e.getLatencyMs() + "ms");
}
```

### 安全告警（异步事件需切主线程）

```java
@EventHandler
public void onDenied(GatewayAccessDeniedEvent e) {
    if (e.getStatusCode() == 401 || e.getStatusCode() == 429) {
        Bukkit.getScheduler().runTask(plugin, () ->
            banTracker.record(e.getIp(), e.getPolicyName()));
    }
}
```

### 自动生成 OpenAPI 文档

```java
@EventHandler
public void onReg(ApiRegisteredEvent e) {
    for (ApiInfo a : e.getApis()) {
        openApi.add(e.getOwnerPlugin(), a.getHttpMethod(), a.getPath(),
                    a.getApiName(), a.getPermission());
    }
}
```

### 生命周期钩子（插件卸载清理）

```java
@EventHandler
public void onUnreg(ApiUnregisteredEvent e) {
    myCache.invalidateOwner(e.getOwnerPlugin());
}
```

## 7.7 注意事项与坑位

1. **事件不可取消**：均未实现 `Cancellable`，仅用于观测。拦截 / 改写请求请用 `registerWebInterceptor` 或 `registerPolicy`。
2. **线程模型**：网关请求类事件异步（HTTP 工作线程），其余事件主线程。异步事件监听器访问 Bukkit API 前务必切回主线程。
3. **1.12.2 限制**：不允许从主线程触发异步事件，故所有同步事件被框架强制主线程派发；API 访问事件也从 worker 线程切回主线程。
4. **监听器异常安全**：框架对 `callEvent` 已 try-catch，单个监听器异常不会中断其他监听器或请求处理，但仍应自行保证健壮。
5. **`ApiInfo` 只读快照**：不持有处理器实例引用，可安全长期持有做文档 / 审计，不会导致插件卸载后内存泄漏。
6. **`player` 字段离线为 null**：权限端点事件携带经 token/cookie 解析的玩家；玩家离线时 `getPlayer()` 返回 null，请配合 `getPlayerName()` 判断。
