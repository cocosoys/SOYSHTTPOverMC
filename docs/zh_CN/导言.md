# 导言

欢迎阅读 **SOYSHTTPOverMC 开发者教程**。

这份文档面向所有希望在 Minecraft 服务器上做 Web 开发的插件作者。无论你是想给自己的服务器做一个网页管理后台、一个对外展示的官网首页，还是想通过 HTTP 接口把游戏数据开放给其他系统，这份教程都会带你从零理解并接入本插件的能力。

## 为什么要做这个插件

在 Minecraft 服务器运营中，我们常常遇到这样的需求：

- **用网页管理服务器**：比如一个浏览器里就能查看在线玩家、执行指令、配置白名单的管理后台，不必每次都进游戏或开 RCON。
- **给服务器做一个官网首页**：玩家打开一个网址就能看到服务器介绍、公告、排行榜、捐赠链接，甚至直接在网页上报名活动。
- **把游戏数据开放出去**：让 Discord 机器人、小程序、第三方网站通过 HTTP 接口读取或写入服务器状态。
- **在群组服（BungeeCord/Velocity）架构下也能统一出网**：代理端口和游戏端口是同一个，浏览器访问的也是游戏服务器的地址。

传统做法是再起一个独立的 Web 服务器（如用 Node、Spring Boot），再通过 RCON 或数据库与 MC 服务器通信。这带来额外的进程、端口、部署与运维成本。

**SOYSHTTPOverMC 的核心思路是：让 Minecraft 服务器自身“变成”一个 Web 服务器。**

它复用服务器原本就在监听的游戏端口（例如 `25565`），在底层网络嗅探第一字节来区分“这是 MC 握手包”还是“这是 HTTPS 请求”。凡是 Web 请求，就经过一条由无头 Bot 建立的 PluginMessage 隧道回环到服务器内部，由网关与网页注册表处理，最终把响应写回同一个连接。对玩家和浏览器来说一切无缝——**不需要额外端口、不需要额外进程**。

> 一句话总结：装上这个插件，你的 MC 服务器既是游戏服，也是一个支持 HTTPS、REST API、静态网页与 ORM 存储的应用服务器。

## 这份教程能带给你什么

读完本教程，你将能够：

1. 在你的插件里**注册注解式 REST API**（类似 Spring MVC 的 `@GetMapping`），用极少的代码暴露 HTTP 接口；
2. 用极低成本**托管网页与静态资源**，并让它们出现在服务器的门户首页导航里；
3. 借助内置的**网关安全链**（TLS、IP 白名单、API Key、限流）保护你的接口；
4. 用一套**统一的 ORM 注解**同时读写 YAML 文件与 SQL 数据库，而不必关心底层细节；
5. 在**群组服**架构下通过隧道安全地调用其它子服的接口；
6. 了解完整的**能力门面 API** 与最佳实践，少踩坑。

如果你还不熟悉插件开发，建议先完成一个“HelloWorld”插件再回来阅读。
