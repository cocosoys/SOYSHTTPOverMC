# 导言

欢迎阅读 **SOYSHTTPOverMC 开发者教程**。

SOYSHTTPOverMC（HTTP-Over-MC）是一个让 Minecraft 服务器自身"变成"Web 服务器的 Spigot 插件：它在服务器原本监听的游戏端口上同时服务 **MC 流量、明文 HTTP 与 HTTPS**，并提供注解式 REST API、网页托管、安全网关、多后端存储与 ORM、国际化等一整套能力。浏览器玩家与游戏客户端共用同一个地址与端口，无需额外进程、无需额外端口。

## 版本支持（真实构建产物）

当前仓库采用多模块 + 版本适配器架构，一份核心源码覆盖多个服务端版本，各版本以独立 jar 产物交付：

| 产物 | 目标服务端 | 同端口嗅探实现 | Java 要求 |
| --- | --- | --- | --- |
| `SOYSHTTPOverMC-1_6-<版本>.jar` | 1.6.4 | 连接级接入（ServerSocket 首包分流） | JDK 7/8 |
| `SOYSHTTPOverMC-1_7-<版本>.jar` | 1.7.10 | relocate netty 反射桥（挂接服务端内嵌 netty） | JDK 7/8 |
| `SOYSHTTPOverMC-1_12-<版本>.jar` | 1.12.2 | Netty pipeline 注入（标准 netty，全功能） | JDK 8 |
| `adapter/v1_16x`、`v1_20x`、`v1_21x`、`v1_26x` | 1.16.x / 1.20.x / 1.21.x / 1.26.x | 各版本反射适配模块（同端口嗅探） | 按版本 JDK |

> 本教程默认以 **Spigot 1.12.2 + Java 8** 为运行示例；所有 API 与配置在其余版本上语义一致。

## 核心能力

1. **同端口三协议共存**：MC 握手、明文 HTTP、HTTPS（TLS 就地升级）共用服务器端口，互不干扰；
2. **注解式 REST API**：`@GetMapping` / `@PostMapping` 等注解暴露 HTTP 接口（类似 Spring MVC），自动带 `/api` 前缀；
3. **网页与静态资源托管**：程序化登记（`WebRegistry`）与配置文件登记（`pages.yml`）双通道，支持昵称路由、跳转、目录托管、缓存与权限保护；
4. **安全网关**：插件式策略链（TLS 强制、IP 白/黑名单、令牌桶限流、访问限制器、统一鉴权），全部以 `gateway/` 目录下的 YAML 配置；
5. **登录插件接入**：AuthMe 等登录插件经 SPI 接入后，网页端可登录、签发会话令牌（JWT），支持"记住我"设备免登录；
6. **多后端存储 + 双后端 ORM**：YAML / SQLite / MySQL 主辅镜像；`@TableName` 实体注解 + `YAML.Pojo` / `SQL.Pojo` 同一套条件链读写；
7. **本地权限表**：内置 `local` 权限提供者（`/soyshttp perm` 管理用户/组/权限），离线与在线统一判定；
8. **国际化**：`language.yml` 切换语言、叠加额外语言源，全插件日志与界面文本均可翻译；
9. **多版本兼容**：adapter 版本模块以反射 / SPI 方式覆盖各版本差异，第三方插件面对的是完全一致的 API。

## 这份教程能带给你什么

读完本教程，你将能够：

1. 在你的插件里**注册注解式 REST API**，用极少的代码暴露 HTTP 接口；
2. 用程序化或配置文件方式**托管网页与静态资源**，并控制访问权限；
3. 借助**安全网关**（TLS、IP 白名单、限流、API Key、会话令牌）保护你的接口；
4. 用一套**统一的 ORM 注解**同时读写 YAML 文件与 SQL 数据库；
5. 在**群组服（BungeeCord / Velocity）**架构下正确配置跨服路由；
6. 理解**能力门面 API**（6 个能力组）与事件系统，完成插件联动。
