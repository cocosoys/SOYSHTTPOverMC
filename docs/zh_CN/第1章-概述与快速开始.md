# 第一章 概述与快速开始

本章先建立对 SOYSHTTPOverMC 的整体认识：它是什么、核心架构如何工作，以及如何把它的能力接入你自己的插件。读完本章，你将能跑通第一个“注册一个接口 + 挂一个网页”的最小示例。

## 1.1 项目简介

SOYSHTTPOverMC 是一个 **Spigot / Paper 1.12.2（Java 8）插件**，它让 Minecraft 服务器在不增加额外端口与进程的前提下，直接对外提供：

- **HTTPS / 明文 HTTP 服务**（与游戏协议共享服务器端口）；
- **注解式 REST API**（仿 Spring MVC，开发者用 `@GetMapping` 等即可暴露接口）；
- **静态网页与门户首页托管**（可把你的官网、管理后台挂到服务器网址下）；
- **网关安全链**（TLS 终止、IP 白名单、API Key 鉴权、令牌限流）；
- **双后端 ORM 存储**（YAML 文件与 SQL 数据库，统一注解、统一 API）；
- **群组服支持**（BungeeCord / Velocity 下经隧道跨服调用，端口依旧只有一个）。

它的价值在于：**服务器即应用服务器**。你不需要再维护一套独立的 Web 后端，所有网页与接口都由 MC 服务器进程直接处理，并通过游戏端口对外服务。

## 1.2 核心架构总览

理解几个关键组件，有助于你正确使用开放 API：

### 1.2.1 端口复用与首包嗅探（SocketSniffer）

服务器启动时监听游戏端口（如 `25565`）。在 Netty 管道最前端的 `SocketSniffer` 会读取连接的首字节：

- 首字节是 MC 握手特征 → 交还 Minecraft 协议正常处理；
- 首字节是 `0x16 0x03`（TLS 握手）→ 当作 HTTPS 请求处理；
- 首字节是明文 HTTP 请求行 → 升级到 TLS（返回 `426`）或直接处理。

这样**一个端口同时承载游戏与 Web 流量**，无需额外监听。

### 1.2.2 无头 Bot 与 PluginMessage 隧道

Web 请求如何进入服务器内部逻辑？本插件在服务器内维持一个**无头 Bot 账号**（非玩家、对真实玩家隐藏），它像普通玩家一样“登录”本服，注册一个 PluginMessage 通道（默认 `httpproxy:main`）。

浏览器发来的 HTTP 请求被封装成 PluginMessage，经这条隧道回环到服务器内部的 `McMessageHandler`，再由**网关（gateway）**与**网页注册表（WebRegistry）**路由处理，最终响应沿原路写回同一个 TCP 连接。

> 对开发者而言：你不需要理解隧道细节。你只需要调用门面 API 注册接口或网页，内部路由会自动完成。

### 1.2.3 开放能力门面（SoysHttpOverMcApi）

本插件对外只暴露**一个总入口接口** `SoysHttpOverMcApi`，它按能力分组再跳转到各子接口。这样每个能力组都独立、可读、可单测，而不是一个庞大的“上帝接口”。

```java
SoysHttpOverMcApi api = HttpOverMcPlugin.getInstance().getApi();
api.getApiRegistration().registerController(new MyApi());   // 能力组 1：注解式 API
api.getWebPage().registerPage(owner, "/hello", bytes);       // 能力组 2：网页
api.getAuthCredential().issueCredential(subject);           // 能力组 3：凭证
api.getToolkit().toJson(obj);                               // 能力组 4：工具
api.getLogger().logInfo("...");                             // 能力组 5：日志
api.getBotManagement().addBot("bot2", "my:chan");           // 能力组 6：Bot
api.getHttpClient().sendGet("https://example.com");        // 能力组 7：HTTP
api.getExtension().registerSubCommand(...);                 // 能力组 8：扩展
api.getCrossServer().callRemoteApi(...);                    // 能力组 9：跨服
```

各能力组详见第六章与附录。

## 1.3 接入前置条件

### 1.3.1 运行环境

- 服务端：Spigot 或 Paper **1.12.2**；
- Java：**Java 8**（插件以 Java 8 字节码构建）；
- SOYSHTTPOverMC 本身已安装并启用；
- 服务器 `server.properties` 中 `online-mode` 必须为 `false`（无头 Bot 以离线模式登录）。

### 1.3.2 plugin.yml 声明依赖

你的插件必须在 `plugin.yml` 中声明 `softdepend`，确保本插件先于你的插件启用（否则 `getInstance().getApi()` 可能取不到）：

```yaml
name: MyPlugin
main: com.example.myplugin.MyPlugin
version: 1.0.0
api-version: 1.12
softdepend: [SOYSHTTPOverMC]
```

> 用 `softdepend` 而非 `depend`：这样即使本插件未安装，你的插件也能正常加载（只是 Web 能力不可用）。在 `onEnable` 中应先判断 `HttpOverMcPlugin.getInstance()` 是否为 `null`。

### 1.3.3 获取门面实例

```java
import com.github.cocosoys.mc.soyshttpovermc.HttpOverMcPlugin;
import com.github.cocosoys.mc.soyshttpovermc.api.SoysHttpOverMcApi;

public class MyPlugin extends JavaPlugin {
    @Override
    public void onEnable() {
        HttpOverMcPlugin holder = HttpOverMcPlugin.getInstance();
        if (holder == null) {
            getLogger().warning("SOYSHTTPOverMC 未安装，Web 功能不可用");
            return;
        }
        SoysHttpOverMcApi api = holder.getApi();
        // 接下来调用 api.getApiRegistration() / api.getWebPage() / ...
    }
}
```

## 1.4 第一个扩展插件：注册接口与网页

下面用最小代码同时暴露一个接口和一个网页。

### 1.4.1 一个最简单的接口

```java
import com.github.cocosoys.mc.soyshttpovermc.annotations.ApiName;
import com.github.cocosoys.mc.soyshttpovermc.annotations.GetMapping;
import com.github.cocosoys.mc.soyshttpovermc.util.AjaxResult;

public class HelloApi {

    @ApiName("问候")
    @GetMapping("/hello")
    public AjaxResult hello() {
        return AjaxResult.success("你好，世界！");
    }
}
```

在 `onEnable` 中注册：

```java
api.getApiRegistration().registerController(new HelloApi());
```

注册后，若网关开启了鉴权，实际路由为 `https://<服务器地址>/api/hello`；未开启鉴权时为 `https://<服务器地址>/hello`。

### 1.4.2 挂一个网页

```java
import java.nio.charset.StandardCharsets;

String html = "<!doctype html><html><body><h1>我的服务器官网</h1></body></html>";
api.getWebPage().registerPage(this, "/site/home", html.getBytes(StandardCharsets.UTF_8));
```

浏览器访问 `https://<服务器地址>/site/home` 即可看到该页面。

### 1.4.3 加入门户导航

让玩家在服务器门户首页直接看到入口：

```java
api.getWebPage().registerNavItem(this, "我的官网", "/site/home");
```

## 1.5 自动卸载机制

你**不需要**在 `onDisable` 里手动清理注册的接口与网页。本插件通过 `ApiLifecycleListener` 监听 Bukkit 插件禁用事件：一旦你的插件被禁用，其名下注册的控制器、网页、导航项、凭证颁发器等会被**自动卸载**，不会残留或泄漏。

> 这意味着：只要在你自己的 `onEnable` 中完成注册即可，生命周期交给本插件管理。

## 1.6 线程模型与注意事项

- **读写存储不要阻塞主线程**：SQL 后端查询是同步阻塞的，`StorageManager` 的写入走单线程串行执行器；在游戏主线程调用 `SQL.Pojo.select(...)` 等可能卡服，应在异步任务中执行。
- **API 处理器内避免重活**：网关在 I 线程中分发请求，长时间阻塞会影响吞吐；重计算请丢到 Bukkit 异步调度或自建线程池。
- **异常统一经 ExceptionBus**：操作失败时门面会构造对应模块异常并广播（结构化日志），随后原样抛出；需要精准捕获时按模块 catch `soys.soyshttpovermc.exception.*` 下的专用异常。
