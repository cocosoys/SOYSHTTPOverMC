# 第1章 概述与快速开始

## 1.1 项目是什么

SOYSHTTPOverMC 是一个运行在 Spigot / Paper 服务端上的插件，它让服务器在**同一个端口**上同时对外提供：

- Minecraft 游戏连接（原样放行）；
- 明文 HTTP 网页 / API；
- HTTPS（网关在嗅探到 TLS 首包后就地挂接 `SslHandler` 解密，无独立端口）。

它的核心是一套**同端口嗅探器（SocketSniffer）**：在服务端监听 socket 上读取第一个数据包，按协议特征区分 MC / HTTP / TLS，分别走不同的处理通道。不同服务端版本通过 `adapter` 模块实现同一效果（见 1.5 节）。

## 1.2 架构总览

```
浏览器 / curl ──┐
                ├──> 服务端监听端口（如 25565）
MC 客户端 ──────┘          │
                          ▼
                  同端口嗅探器（按首包分流）
                 MC  ────────────────> 原 MC 处理链（原样放行）
                 TLS ──> SslHandler ──> HTTPS 请求
                 明文 HTTP ──────────> 安全网关（GatewayFilter）
                                          │
                    策略链：TLS强制 → IP白名单 → 限流 → 鉴权 → 访问限制器
                                          │
                    ┌─────────────────────┼─────────────────────┐
                    ▼                     ▼                     ▼
             注解式 API 路由        网页路由（WebRegistry）  独立服务器模式后端
           （/api/*，控制器）    （/web/plugins/<插件>/...、pages.yml）
```

模块划分（Maven 多模块）：

| 模块 | 职责 |
| --- | --- |
| `common` | 与 Bukkit 无关的纯逻辑：注解定义、ORM、存储抽象、i18n、SPI（Platform / ConfigSection）、proxy 探测工具 |
| `core` | 主插件本体（Bukkit 依赖）：上帝类 + 代理类、API 门面、网关、网页、命令、权限、存储装配 |
| `adapter/common` | 版本兼容工具（无 Bukkit 引用，全部反射调用）：ServerVersion、SocketSnifferAdapter、兼容工具 |
| `adapter/v1_6x` 等 | 各版本适配模块：嗅探器安装器、Platform 覆盖、JdbcCompat、YamlIo |

> 群组服代理模块（SOYSHTTPOverMC-Proxy，BungeeCord）为独立项目单独构建，不在此仓库内。

## 1.3 安装与产物

1. 从构建产物中选择与你的服务端版本匹配的 jar（见导言表格），放入 `plugins/`；
2. 首次启动：插件会生成 `EULA.yml`、`config.yml`、`pages.yml`、`language.yml`、`gateway/` 目录与 `web/` 前端资源目录；
3. **必须先同意 EULA**：编辑 `plugins/SOYSHTTPOverMC/EULA.yml`，把 `eula: false` 改为 `eula: true`，否则插件直接禁用（控制台提示协议内容）；
4. 重启或 `reload` 服务端，看到启动 Banner 即成功。

启动完成后日志会给出关键信息：运行拓扑（独立服 / BungeeCord / Velocity）、HTTP 后端模式、网关与 HTTPS 状态、API 注册数、web 根目录。

### 1.3.1 快速自检

```text
/soyshttp status      # 本服地址/端口/后端模式/嗅探器/网关/HTTPS/注册数
/soyshttp pages       # 已登记的网页
/soyshttp api         # 已注册的注解式 API 端点
/soyshttp tokens      # 已颁发的会话令牌
```

浏览器访问 `http://<服务器IP>:<端口>/` 应看到默认首页（`web/` 或 jar 内置 `dist/`）。

## 1.4 插件数据目录结构

```
plugins/SOYSHTTPOverMC/
├── config.yml            # 主配置（mc/sniffer/http-backend/log/permission/storage）
├── EULA.yml              # 使用协议（eula: true 同意）
├── pages.yml             # 前端 web.* 配置 + 手动网页登记 + 网页权限
├── language.yml          # 国际化（current/rule/sources）
├── language/             # 语言包（zh_cn.yml / en_us.yml）
├── gateway/
│   ├── config.yml        # 网关总开关 / api-prefix / debug-events
│   ├── https.yml         # TLS 证书与协议设置
│   ├── policies/         # 安全策略（auth / ip-allowlist / rate-limit / access-limiter / tls）
│   └── issuers/          # 凭证颁发器（session-token.yml）
├── web/                  # 前端磁盘根（首次启动从 jar 内置 /dist/ 解压）
├── data/                 # YAML 存储与 ORM 数据目录（soys_records.yml + 各表 .yml）
├── data/records.db       # SQLite 存储（启用时）
└── token.key             # 本地 JWT 密钥（自动生成）
```

## 1.5 各版本实现差异（重要）

| 能力 | 1.12.2 | 1.7.10 | 1.6.4 |
| --- | --- | --- | --- |
| 同端口嗅探 | Netty pipeline 注入 | relocate netty 反射桥 | 连接级接入（反射替换 ServerSocket） |
| `http-backend.mode` | 四种模式全功能 | direct / memory-queue / netty-eventloop（standalone 可用） | direct / memory-queue / netty-eventloop（standalone 可用） |
| SQLite / MySQL | 服务端自带较新驱动 | adapter JdbcCompat 自动兼容旧驱动 | adapter JdbcCompat 自动兼容旧驱动 |
| TLS | 视运行 JDK | 视运行 JDK | 视运行 JDK（JDK7 上限 TLSv1.1/1.2） |
| config.yml 编码 | UTF-8 | 必须 UTF-8 保存 | 必须 UTF-8 保存 |

> 1.6.4 / 1.7.10 的 Bukkit `YamlConfiguration` 按平台编码（Windows=GBK）读取，adapter 已覆盖为显式 UTF-8 读取，但**配置文件本身务必用 UTF-8 保存**，勿用记事本默认 ANSI/GBK。

## 1.6 /soyshttp 命令总览

主命令 `/soyshttp`（简写 `/shttp`），需要 `soyshttp.admin` 权限（默认仅 OP）。

| 子指令 | 用途 |
| --- | --- |
| `/soyshttp reload` | 热重载：日志级别、语言、pages.yml、存储、网关策略与 TLS、登录桥、网页登记 |
| `/soyshttp key <主体>` | 为指定主体下发最高权限凭证（静态 Key，令牌带 `adm` 标记） |
| `/soyshttp send <url\|/page> [显示文字] [玩家]` | 向玩家发送可点击链接 |
| `/soyshttp pages [all]` | 查看已登记的网页（默认仅 .html 页与跳转） |
| `/soyshttp api` | 查看已注册的注解式 API 端点（方法/路径/owner/权限） |
| `/soyshttp tokens` | 查询所有已颁发的会话令牌 |
| `/soyshttp lang [代码]` | 查看/切换语言（`lang sources ...` 管理额外语言源） |
| `/soyshttp perm ...` | 本地权限表管理（组/用户 CRUD + 检查，配套 `offline-fallback: local`） |
| `/soyshttp log-level <级别>` | 动态调整日志级别（OFF/ERROR/WARN/INFO/DEBUG/TRACE） |
| `/soyshttp migrate <yaml\|sql> <yaml\|sql>` | ORM 两个后端（YAML/SQL）之间显式迁移 soys_records 数据 |
| `/soyshttp status` / `report` / `eula` / `help` | 状态 / 数据贡献上报 / EULA 查看 / 帮助 |

## 1.7 接入第一个第三方插件

### 1.7.1 前置

在你的 `plugin.yml` 声明软依赖：

```yaml
softdepend: [SOYSHTTPOverMC]
```

### 1.7.2 获取门面

```java
public class MyPlugin extends JavaPlugin {

    @Override
    public void onEnable() {
        // 情况 A：本插件加载晚于 SOYSHTTPOverMC —— 直接取
        HttpOverMcPlugin soys = HttpOverMcPlugin.getInstance();
        if (soys == null) { getLogger().warning("SOYSHTTPOverMC 未加载，跳过接入"); return; }
        SoysHttpOverMcApi api = soys.getApi();
        // 注册一个注解式控制器（能力组 1）
        api.getApiRegistration().registerController(new MyApi());
        // 登记一个网页（能力组 2）
        api.getWebPage().registerPage(this, "/hello",
                "<h1>Hello from MyPlugin</h1>".getBytes(StandardCharsets.UTF_8), "text/html");

        // 情况 B：本插件可能先于 SOYS 加载 —— 监听 SoysReadyEvent 延迟注册
        getServer().getPluginManager().registerEvents(new Listener() {
            @EventHandler
            public void onReady(SoysReadyEvent e) {
                e.getApi().getApiRegistration().registerController(new MyApi());
            }
        }, this);
    }
}
```

### 1.7.3 自动卸载

第三方插件名下的 API 与网页在插件禁用时由 `ApiLifecycleListener` **自动卸载**，无需手动清理；也可显式调用 `api.getWebPage().unregisterPluginPages(插件名)` / `api.getApiRegistration().unregisterPluginControllers(插件名)`。

### 1.7.4 注册热重载钩子

如果你的插件有自己的配置，希望在 `/soyshttp reload` 时一并刷新：

```java
api.registerReloadHook(() -> {
    myConfig.reload();
});
```

等价地，也可以监听 `HttpConfigReloadEvent`（见第 7 章）。

## 1.8 多版本打包（构建侧）

仓库用 Maven 多模块 + 版本 profile 一次产出多个 jar：`core` 与 `common` 保持 Java 8 字节码，`adapter` 各版本模块按目标版本选择 spigot-api 依赖与编译 JDK（见第 6 章 6.8 节）。开发第三方插件时，直接依赖 `soyshttpovermc-common`（无 Bukkit 依赖，可在任意 JDK 编译）即可使用注解与 ORM；需要门面 API 时依赖 `soyshttpovermc-core` 或直接以 `softdepend` 方式运行时接入。
